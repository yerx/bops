# Selective routes

All names below denote adopted methods until installation and invocation are verified. Read only the relevant row. Apply the bundled policy's operating contract, selective adoption catalog and authorization gates, subordinate to the target repository instructions.

| Intent / trigger | Smallest useful sequence and output | Verification and return |
| --- | --- | --- |
| Feature; new accepted behavior | Clarify consequential ambiguity (Matt grill/domain/spec); tickets only for substantial independent slices; implement/TDD. Output bounded acceptance and changed behavior. | Public-seam behavior plus failure cases; independent Standards/Spec review. Shared auth/storage/API adds blast-radius. Agree the architecture checkpoint before implementation when a structural decision is needed. |
| Bug fix; reproducible defect or uncertain cause | Matt diagnosing-bugs/how; reproduce and distinguish environment/test/product; smallest root-cause repair with regression. | Demonstrate original failure then acceptance with normal entrypoint. Existing guard/history invokes why; unrelated defects queue. |
| Behavior-preserving refactor | Record invariants and callers; scoped deslop or staged migration; no speculative feature change. | Behavioral baseline, affected callers and integration checks; do not delete legacy until deployment/caller constraints are satisfied. |
| Read-only investigation | how/why plus evidence pointers and competing hypotheses. Output supported findings and next diagnostic. | Inspect source/history/receipts; no patch, install, dispatch or runtime side effects beyond stated read-only scope. |
| Scheduled bug scout | Observe, fingerprint/deduplicate, queue, cluster for pattern review. Output findings and confidence. | Finding does not authorize repair, scheduling or publication. Honor an explicit pre-existing scheduled repair scope if supplied; otherwise propose one approved root-cause experiment. Escalate urgent data-loss/security without auto-fix. |
| Architecture audit | Map boundaries/valid states/dependencies; architect/blast-radius as needed; compare smallest viable options. | Evidence-backed findings and checkpoint before implementation. Read-only audit cannot become migration. Preserve no-Dune decision absent new explicit authorization. |
| Performance / benchmark | benchmark-checklist: define claim, representative baseline/configuration, limiter, output/error checks, real work, warm/cold state, repeated alternating comparisons (normally at least five each), median/range and end-to-end impact. | Isolate profiling from timing; record resources/version/runtime/spend. Insufficient noise/config/error/work evidence means inconclusive. One-run ballpark only if explicitly requested and labeled; no decision-grade speedup claim. |
| Documentation | Minimal source-grounded edit and attribution; technical-writing/teach only when complexity warrants. | Check links, version agreement and factual scope; do not mirror implementation with tests or rewrite historical evidence silently. |
| Session learning | Matt sampled retro; repeated classes use correct/reflect through observation promotion; existing journal supplies show-me-your-work. | Review failures/high-risk plus sampled passes; approve one intervention, negative/valid-positive checks, false positives/cost and rollback. No automatic policy/AGENTS edits or new recurring task. |

TypeScript paths may add typescript-best-practices: validated unknown boundaries, derived types and valid states using repo conventions. Swift paths use actual Swift/domain conventions; never impose TypeScript tooling on them. Ambiguous stack means inspect manifests/paths or ask before dependent selection. Preserve useful license/safety/explanatory comments. No blanket swarm or full poteto-mode.
